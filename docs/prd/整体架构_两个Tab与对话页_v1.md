## 一、一句话看懂整个架构

**Tab1 的意义是输入生成内容，Tab2 的意义是让用户练习和成长。**

这不是「同一批内容的两种看法」，而是**两个功能阶段**：Tab1 进料，Tab2 加工和产出。

```
Tab1 · Today：输入生成            Tab2 · Library：练习与成长
  用户说一段生活                    把素材变成「我能说出口的」
  AI 生成学习卡片          ──▶     ├─ 入口：按分类组织的话题卡（开口的入口）
  素材落库                          ├─ 对话页：练习执行（1.0.0 关闭）
                                    └─ 成长层：练得怎样（未做）
                          账本在两者之间记账（用户看不见）
```

**对话页不是第三个并列的 Tab，它是 Tab2 的练习执行页**——从 Tab2 发起，练完回 Tab2。App 只有两个 Tab：`Today` 与 `Library`（`AppTab`）。

**判断任何新功能该放哪，只问一句：它是在「造素材」还是在「把素材变成能力」。** 前者归 Tab1，后者归 Tab2。

## 二、Tab2：开口的入口

### 2.1 定位（相对 v2 的核心变化）

v2 把 Tab2 定为「以词条为中心的练习清单」。**后来产品负责人拍板调整**（设计方案 v2 §十 #5、§九）：

- **Tab2 = 开口的入口**，词库是佐证。用户进来的第一件事是「聊哪个话题」，而不是翻词表。
- **练习的入口是大分类**（设计方案 #8）；子场景只作卡片描述、不可点；收窄发生在对话里。
- **`Your words` 推迟**，定位改为记单词工具，场景只是帮助记忆。
- **账本不是被砍掉，而是换了角色**：记账与记忆层。它仍是实时推荐的弹药、「进步」北极星指标的来源、成长层的唯一数据源。**推迟的是界面，不是账本。**
- 「整段回看某次经历」仍归 Tab1。Tab2 里的场景是**练习单元**，不是可浏览的内容卡。

### 2.2 1.0.0 的首屏（代码：`Mine/MineView.swift`）

两种状态，同一页面：

| 状态 | 展示 |
|---|---|
| **待解锁**（`Tab2LockedView`） | `Topics in progress`：各分类的词汇进度（词数 / 20，可展开看词）；一个分类都没有时显示空态；底部按钮引导回 Tab1 去捕捉 |
| **已解锁**（`Tab2UnlockedView`） | `Talk about today`（Hero 话题卡）→ `More to talk about`（更多话题行）→ `Topics in progress`（尚未解锁的分类，带词数进度） |

区块显隐规则（`MineView` 内的纯函数，有单测）：0 个解锁分类 → 整块不渲染；只有 1 个 → 有 Hero、无 More；三块全空 → 空态页。

**点击一张话题卡 → 进入对话页。** 1.0.0 中 `FeatureFlags.conversationEnabled = false`，点击只弹出 "Speaking mode will be available soon."。

### 2.3 解锁规则

- **每个分类各自在 20 个去重、活跃的词条时解锁**；查词来的词条计入；`scene_category` 为空的词条不计入任何分类。
- **Tab2 整体开门** = 任一分类达标（≥ 20 词）即可。早期方案里「Tab1 累计 ≥ 5 次输入」的条件已于 2026-08-04 移除（迁移 `20260804000000_tab2_unlock_words_only.sql`，现行定义见 `get_tab2_home` v6），客户端也不再展示输入次数。
- **永不回锁**：一旦解锁，即使之后删素材使条件不再满足，也保持解锁（本地持久化标记）。
- 细则与口径：以 `get_tab2_home` 的最新迁移为准；`Tab2首页_实现规范_v1.md` §2.1 仍写着旧的两个条件，已标注过期。

### 2.4 对话页（Tab2 的练习执行页）

- 独立页面，从 Tab2 发起，沉浸式语音；不是默认屏。
- 代码已有（`Conversation/`、`DialogueService.swift`、`dialogue` Edge Function、`dialogue_turns` 表），1.0.0 通过开关关闭；打开前必须先读 `FeatureFlags.swift` 里的权限声明警告。
- 设计依据：`对话页与成长层_需求设计_v1.md`、`对话页_UI与组件规范_v1.md`、`对话页_接口契约_v1.md`、`对话页_Prompt设计与全文_v1.md`。

### 2.5 成长层（未做）

- 读账本 + 读用户实际说出口的话，只**陈述现状、不评价、不打分**。
- 依赖对话页产生数据，因此排在对话页之后。入口形态未定，不做第三个底部 Tab。

## 三、Tab1：输入生成

### 3.1 现状（1.0.0）

- 对话流：用户气泡 + AI 卡片 + 日期分隔符交替排列，底部输入框（`Today/`：`MessageRow`、`AICardBody`、`InputBar`）。
- 输入：文字、拍照/相册。历史全部保留，失败可重试，重试保持原位。
- 配套：首次启动的 Onboarding（含 AI 使用同意 `AIConsentView`，并生成第一张卡）、每日用量上限（`UsageLimitButton`）、设置与反馈（`Settings/`）。
- **边界**：Tab1 不做分类整理（异步进行，用户手动切 Tab 才看到结果）；不做练习入口；不做往复对话（那是对话页）。

### 3.2 未来目标形态（未排期）

纯浏览态内容库 + 单入口条 + 全屏独立输入态（自带引导、历史入口、附件/相机/语音）。这是「目标在哪里」，不是当前计划。语音、长文输入同样**未做**。

## 四、数据关系：账本是交汇点

```
        Tab1 输入                        对话页（Tab2 的练习执行）
     （一次输入一张卡）                     （一来一回说出来）
            │            两个入口都往账本记账            │
            ▼                                          ▼
   ╔═════════════════════════════════════════════════════╗
   ║  词汇账本 lexicon = 记账与记忆层                       ║
   ║    lexicon_entries      去重后的词条                   ║
   ║    lexicon_occurrences  每次使用的流水（练习证据）      ║
   ║    learning_events      弱点 / 错误 / 进步（已建表）    ║
   ╚═════════════════════════════════════════════════════╝
                              │
                              ▼
                  Tab2 话题卡 · 实时推荐 · 成长层
```

- `materials` / `messages` 结构不变，账本是并行长出来的一层。
- Tab1 的记账由 `generate` 的 Stage 3 完成（后端已上线）。对话产出的记账 RPC（`record_lexicon_dialogue_units`）已建好，但**尚未被任何 Edge Function 调用**，随对话页打开时一并接线。
- 字段设计见 `Agent内容组织与成长系统_PRD_v2.md`，本文不重复。

## 六、确定 / 待定

### 已确定

1. **Tab1 = 输入生成内容；Tab2 = 让用户练习和成长。** 按功能阶段划分。
2. **对话页 = Tab2 的练习执行页**，不是第三个并列的面；从 Tab2 发起、不作主屏。
3. **Tab2 = 开口的入口**；练习入口是大分类；`Your words` 推迟。
4. **账本 = 记账与记忆层**，后端继续跑，是实时推荐、北极星指标与成长层的数据源。
5. 解锁制：每个分类 20 词各自解锁；任一分类达标即整体开门；永不回锁。
6. 成长层只陈述事实，不评价、不打分。

### 待定

| # | 待定项 | 影响面 |
|---|---|---|
| 1 | 对话页何时打开；打开前要补齐权限声明与上架合规 | 1.0.x 以后 |
| 2 | 「进步」的定义（说不出→说出来 / 说错→说对 / 卡顿→流畅） | 北极星指标 |
| 3 | onboarding 生成的素材是否记进账本（首次进 Tab2 是否为空） | 新用户首次体验 |
| 4 | Tab1 未来形态的底部入口（输入 / 提问）分别是什么 | 未来规划 |
