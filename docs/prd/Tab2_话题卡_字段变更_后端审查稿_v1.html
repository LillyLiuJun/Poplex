01变更方向

一句话：复活 sub_scenes，退休 featured。

featured 的语义是「整个类别挑一条样本素材」；新卡面需要的是 「该类别下各个复现活动，每个带自己的次数和图」——正是 sub_scenes 的形状。

注意方向是反的。 第 2 刀（20260812020000）曾用 featured 替代 sub_scenes，migration 中 sub_scenes 标注为 「旧结构，§9.5 并行保留；前端切新字段后的清理刀再删」。本次取消那次清理，反向执行。 若当初该设计有本稿未理解的意图，请指出。

03SQL 改动点

逐 CTE 说明。基线为 get_tab2_home_hero_v4。

3.1 cat_words —— 加 not_spoken_count，删 last_material_at

cat_words AS (
  SELECT
    lo.scene_category,
    COUNT(DISTINCT lo.entry_id)::int AS word_count,
    COUNT(DISTINCT lo.entry_id) FILTER (WHERE le.spoken_count = 0)::int
                                     AS not_spoken_count,
--  MAX(lo.created_at)               AS last_material_at,   -- 删
    ( ... preview_words 子查询，去留见 §7-8 ... )
  FROM   lexicon_occurrences lo
  JOIN   lexicon_entries     le ON le.id = lo.entry_id
  WHERE  lo.user_id = p_user_id
    AND  lo.scene_category IS NOT NULL
    AND  le.status = 'active'
  GROUP  BY lo.scene_category
)

3.2 last_talked —— 新 CTE

last_talked AS (
  SELECT scene_category, MAX(created_at) AS last_talked_at
  FROM   dialogue_sessions
  WHERE  user_id = p_user_id
    AND  scene_category IS NOT NULL
    -- 口径待确认，见 §7-2 / §7-3
  GROUP  BY scene_category
)

最终 LEFT JOIN 到 category 上；无行 → last_talked_at = null， 客户端渲染为 Never talked。

3.3 activities —— 由 sub_scenes 收窄改造

保留 scene_detail + occurrence_count； 删 quote / target_expression； image_url 改为嵌套的 cover 对象并补 material_id。 

activities AS (
  SELECT
    sc.scene_category,
    jsonb_agg(
      jsonb_build_object(
        'scene_detail',     sc.scene_detail,
        'occurrence_count', sc.occurrence_count,
        'cover',            cover.obj          -- null 表示该活动无带图素材
      )
      ORDER BY sc.occurrence_count DESC, cover.latest_at DESC NULLS LAST
    ) AS items
  FROM scene_counts sc
  LEFT JOIN LATERAL (
    -- 每个活动取「最新的一条带图 material」作封面
    SELECT jsonb_build_object('material_id', m.id, 'image_url',
             m.raw_content->>'source_image_path') AS obj,
           m.created_at AS latest_at
    FROM   lexicon_occurrences lo
    JOIN   materials m ON m.id = lo.source_id
    WHERE  lo.user_id        = p_user_id
      AND  lo.scene_category = sc.scene_category
      AND  lo.scene_detail   = sc.scene_detail
      AND  m.raw_content->>'source_image_path' IS NOT NULL
    ORDER  BY m.created_at DESC
    LIMIT  1
  ) cover ON true
  WHERE sc.occurrence_count > 0
  GROUP BY sc.scene_category
)
排序 tiebreak 需确认。occurrence_count 相同时用封面时间兜底， 但无封面的活动会因 NULLS LAST 永远排在同分组末尾——这是否可接受？ 另一选项是用 MAX(lo.created_at)（该活动最后一次出现），与有无图无关，顺序更稳定。见 §7-5。

3.4 featured / hero_photos —— 整段删除

featured CTE 的三层排序（照片优先 → 方向×粒度 → 意图明确度 → 场景高频 → created_at） 全部移除。hero_photos CTE 及其 ROW_NUMBER() OVER (PARTITION BY ...) 窗口一并移除。

删除后 featured 的 12 个子字段全部消失，其中 input_lang / source_direction / source_granularity / spoken_count 仅服务于该 CTE 的排序，无其他消费者。

04正确性陷阱（重点）

not_spoken_count 必须 DISTINCT，否则虚高

cat_words 的 FROM 是 lexicon_occurrences JOIN lexicon_entries， 按 scene_category 分组——一个词条在多条 occurrence 里出现就会被数多次。 写成 COUNT(*) FILTER (WHERE le.spoken_count = 0) 会得到「出现次数」而非「词条数」。

必须是 COUNT(DISTINCT lo.entry_id) FILTER (...)，与旁边 word_count 的写法一致。

同一个坑本项目已中过一次：scene_counts CTE 的注释写着 「修正点：旧为 COUNT(*)（词条行数，虚高）→ 现为 COUNT(DISTINCT source_id) FILTER (非 word)」。请在 review 时专门确认这一行。

05连带影响

5.1 Edge Function 的图片签名链路必须同步改

signImagePaths() 现在从三处收集 Storage 路径： sub_scenes[].image_url、featured.image_url、hero_photos[].image_url。 改造后路径只存在于 activities[].cover.image_url（多一层嵌套）。

收集与回写两段都要改。漏改的后果是静默的：签名 map 命中不到， sign() 返回 null，客户端拿到无图的 cover，页面全量退兜底图但不报错。

5.2 客户端模型

删除 Tab2FeaturedMoment / Tab2HeroPhoto； Tab2SubScene 改造为 Tab2Activity + 嵌套 Cover。 Tab2CategoryData 的 init(from:) 中相关 decodeIfPresent 分支一并调整。

5.3 老客户端兼容 —— 静默降级，不崩

06性能与索引

  • 不需要新建索引。idx_lexicon_entries_user_spoken (user_id, spoken_count) 与 idx_dialogue_sessions_user_created (user_id, created_at DESC) 均已存在。
  • 净变化预计为负（更快）。删掉的 featured（多列排序的 DISTINCT ON）与 hero_photos（窗口函数 + 嵌套 DISTINCT ON） 成本高于新增的一个 MAX 聚合。
  • 新增成本集中在 activities 的 LATERAL 子查询： 每个 scene_detail 一次。按现有 prompt 的抽象度，单类别通常 3–5 个活动， 单用户全类别约 30–60 次。请评估这个量级是否需要改写为窗口函数一次算完。
  • last_talked 的分组走 (user_id, created_at DESC) 索引取 user 分区后聚合， scene_category 上无索引。当前数据量下应可接受，请确认。
  • 权限不变：RPC 仍为 SECURITY DEFINER，已 REVOKE FROM PUBLIC, anon, authenticated / GRANT TO service_role。

07需要后端确认的 8 项

纯技术口径与实现选择，不含产品取舍。

1

not_spoken_count 的 DISTINCT 写法

见 §4。请确认最终 SQL 用的是 COUNT(DISTINCT lo.entry_id) FILTER 而非 COUNT(*)。

2

「聊过」的口径：进行中的 session 算不算？

dialogue_sessions.ended_at IS NULL 表示进行中。 last_talked_at 是否应只统计已结束的 session？ 若统计进行中的，用户点进去又立刻退出也会被记为「聊过」。

3

空 session 算不算「聊过」？

turn_count = 0 的 session（建了但一句没说）是否应排除？ 建议 turn_count > 0，请确认是否有反例。

4

dialogue_sessions.scene_category 的取值与 lexicon 侧是否严格一致

两侧都是中文枚举 text 且均 nullable，但没有外键或 CHECK 约束保证一致。 若曾出现过枚举漂移，LEFT JOIN 会静默失配（表现为「永远 Never talked」）。

5

activities 的 tiebreak 用封面时间还是活动最后出现时间

见 §3.3 的 note。用封面时间会让无图活动在同分数段永远垫底； 用 MAX(lo.created_at) 与有无图解耦，顺序更稳定。

6

activities 返回条数上限

卡面只用前 3 条。建议返回前 5 条（为无图时的兜底查找留余量）+ activity_count 全量计数， 避免 payload 随使用时长线性膨胀。请确认这个截断放在 SQL 还是 Edge Function。

7

「其他 类别排除在 Hero 候选之外」放在服务端还是客户端

classifyScene 失败时兜底写 其他，该类别是垃圾桶，会长期「欠账最多」而反复被选为 Hero。 排除规则是写进 RPC，还是留给客户端选取逻辑？

8

preview_words 立刻删还是留一版

改造后归零消费，且它是 cat_words 里一个带 DISTINCT ON 的相关子查询，有成本。 留一版的风险是它像 sub_scenes 一样以「并行保留」之名长期滞留。

  • ② 改 RPC（本稿全部内容）
  • ③ 改 Edge Function 的 signImagePaths（与 ② 同发，见 §5.1）
