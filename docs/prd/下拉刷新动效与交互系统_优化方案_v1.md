# 下拉刷新动效与交互系统 · 优化方案与规范 v1

> **所属模块**：全局基础动效与交互体验 (Global Motion & Interaction)<br>
> **设计调性**：Warm Minimalism + 效率第一 (Warm Editorial, Zero Mechanical Spokes)<br>
> **适用范围**：Tab1 (Today 时间线)、Tab2 (Library 词汇账本)<br>
> **文档版本**：v1.0 (2026-08-26)

---

## 一、 设计背景与定位

下拉刷新（Pull-to-Refresh）在产品中不仅仅是一个单纯的数据加载动画，更是**用户在断网恢复、切换页面或完成生成后「主动获取数据确定性」的核心闭环手势**。

过去系统默认的 12 矩形生硬菊花和亮橙色，带来了强烈的**“机械齿轮感”与“视觉压迫”**，与产品手工纸质（Warm Editorial）温润沉静的气质严重脱节。

本方案旨在建立一套**「零短杠、呼吸感、跟随手势渐进展开、具备超时安全阀」**的温润下拉刷新体系。

## 三、 全生命周期 5 阶段交互规范 (Interaction Lifecycle)

完整的下拉刷新交互必须具备以下 5 个严格时序阶段：

```
 用户手指拖动       系统确认刷新        请求执行          数据返回          系统收起
 [1. 拉伸阶段] ──► [2. 真实触发] ──► [3. 悬停流转] ──► [4. 锚点对齐] ──► [5. 阻尼离场]
  渐进显现/聚拢      单次轻触感反馈      最长 8 秒          数据插入         原生回弹
```

### 1. 阶段 1 · 随手势拉伸展开 (Pulling Phase)
* **拉伸阻尼**：完全沿用 iOS 滚动容器的原生橡皮筋物理，不自行改写滚动偏移。
* **渐进视觉响应**：
  - 下拉不足 `15pt`：指示器保持隐藏，防止轻微滑动误露；
  - 下拉约 `15 ~ 60pt`：透明度由 `0%` 线性升至 `100%`，水珠轨道半径由 `11.5pt` 向心收拢至 `8.5pt`。

### 2. 阶段 2 · 真实触发反馈 (Refresh Start & Haptic)
* **触发归属**：是否进入刷新由系统 `.refreshable` 决定，不用自算距离模拟系统未公开的 armed 状态。
* **单次震动反馈**：仅在系统确认刷新 action 开始执行时触发一次 `UIImpactFeedbackGenerator(style: .light)`，保证触感与真实请求一一对应。

### 3. 阶段 3 · 悬停旋转与加载 (Hover & Spin Phase)
* **悬停与占位**：交给系统 `UIRefreshControl` 管理，跟随系统版本和设备的原生刷新布局。
* **匀速旋转**：方案 C 珍珠水滴开始以 **`1.2s`** 周期匀速旋转（`linear.repeatForever`）。
* **防重复并发**：刷新期间锁定防重入闸门，用户再次下拉或快速滑动不发起重复请求。

### 4. 阶段 4 · 数据对齐与锚点保护 (Alignment & Viewport Safety)
* **底部/顶部自适应**：
  - 若用户在下拉前处于顶部：新数据加载完成后，列表自然撑开，用户视野维持在最新条目；
  - 若用户在被动更新（后台唤醒等）：保持当前阅读条目锚点，绝不强行将用户拽回顶部。

### 5. 阶段 5 · 原生回弹离场 (Retract Phase)
* 数据成功、失败或超时后结束 async refresh action，由系统 `UIRefreshControl` 负责回弹和占位收起。
* 自定义珍珠只跟随 `isRefreshing` 启停，不与系统在同一几何属性上叠加另一套回弹动画。

## 四、 方案 C（珍珠流水滴串）详细参数规范

```
              ● 龙头水珠 (3.0pt / 100% Opacity)
           ○     ○ 第 2 颗 (2.6pt / 85%)
          ○       ○ 第 3 颗 (2.2pt / 65%)
           ·     · 第 4 颗 (1.8pt / 45%)
              · 第 5/6 颗 (1.4pt / 1.1pt / 30% / 18%)
```

* **总尺寸**：外接矩形 `24pt × 24pt`。
* **旋转公转半径**：`8.5pt`（水滴圆心至指示器中心的距离）。
* **水滴梯队配置**：
  - 龙头珍珠：直径 `3.0pt`，初始角度 `0°`，透明度 `100%`
  - 第 2 颗：直径 `2.6pt`，初始角度 `45°`，透明度 `85%`
  - 第 3 颗：直径 `2.2pt`，初始角度 `90°`，透明度 `65%`
  - 第 4 颗：直径 `1.8pt`，初始角度 `135°`，透明度 `45%`
  - 第 5 颗：直径 `1.4pt`，初始角度 `180°`，透明度 `30%`
  - 第 6 颗：直径 `1.1pt`，初始角度 `225°`，透明度 `18%`
* **主色调**：`AppTheme.Color.refreshIndicator`（极淡浅暖灰 `#C7C3BD`）。

## 五、 异常边界与鲁棒性防护体系

1. **8 秒超时硬安全阀 (Timeout Watchdog)**：
   - 手动下拉刷新任务使用墙钟超时竞速；Tab1 / Tab2 均为 8 秒；
   - 一旦超过 8 秒未返回，强制终止 loading 状态、触发回弹收起，并弹出轻量 Toast：*"Couldn't refresh. Try again in a moment."*（落地时已与首载失败错误页统一为同一条，见 `Toast重构与两元语义规范_v1.md` 文案矩阵第 3 行；本方案原稿文案「Unable to sync right now. Pull to try again.」作废）。
2. **断网反馈 (Offline Feedback)**：
   - 手动刷新失败后结合系统网络状态区分离线与一般同步失败；离线时提示检查连接，缓存内容保持不变。
3. **空状态全兼容 (Empty State Usability)**：
   - 无论页面是有数据还是空状态（EmptyStateView），均封装在统一的下拉滚动容器中，确保新用户可随时下拉拉取初始化数据。
