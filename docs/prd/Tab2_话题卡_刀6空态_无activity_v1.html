只有词的类目

解锁门槛是 word_count ≥ 20，而查词也算词——**但词卡的 scene_detail 永远是 null**。 所以一个主要靠查词的用户，完全可能有一个 47 词、已解锁、零 activity 的类目。 这不是数据异常，是设计的必然结果。下面是它在两处的样子。

没有封面。封面来自 activity 的素材，没有 activity 就没有照片—— 走预设图标底。这和刀 6 定的规矩自洽：有照片 = 存过东西，有图标 = 还没画面。 图标底是浅色，所以标签与理由胶囊换成浅底深字的一套。

关键：占位不是两行槽。两行槽 69pt 是为「多颗胶囊可扫视比较」存在的， 这里只有一行字，按单行文本的自然高度走——卡片比有活动时矮一点，矮得有理由。 文案用 sans + textMuted，不用衬线：衬线是用户内容的标记，这是系统在说明状态。

B2 · 给一句话 和 Hero 同一句、同一档。代价：它和下面那行 31 words 说的是同一件事。

画出来之后我改了看法的地方：B2 的问题不是「噪音」，是「重复」。 我原先说一行里塞否定句是噪音——不准确，Only words so far 并不是否定句。 真正的毛病是它紧挨着 31 words，两行说的是同一件事， 而 Hero 那边隔着一整个卡身、中间还有标题，重复感弱得多。

所以如果要给 More 一句话，更该考虑的是让它顶替 N words 那一行， 而不是加在它上面。但那样就丢掉了词数这个真实数字——不值得。

决定 · 2026-09-16 拍板 用 B2，接受与词数重复。一致性压过简洁——同一个状态在两处说同一句话， 规则少一个例外。实现以本决定为准：More 空态渲染一行 Only words so far （与 Hero 同一句、同一档样式），N words 保留在其下方。

两种行高混在一列里不乱，反而更清楚：高的行有内容、矮的行只有词， 一眼就分得出来。这正是固定两行槽那条规矩的本意—— 让同一类的行可以比较；而这两种本来就不是同一类， 高度不同恰恰是在说这件事。

两处都不变：类别名、时间、N words、理由胶囊、Start talking、点击行为

Only words so far 不是新文案——它已经在 Tab2CardLabels.reasonLine 里，作为 lastMaterialAt == nil 的兜底。 而那个分支实际上永远不可达（RPC 的 last_material_at 取的是所有 occurrence 的 MAX(created_at)，查词也算），所以：一，用在这里 不会和理由胶囊在同一张卡上撞车；二，这句好文案终于有了真正的用处。

附带一笔账：那个不可达分支要么删掉、要么写明为什么留着。 留一段永远不执行的代码，下一个人会以为它是活的。
