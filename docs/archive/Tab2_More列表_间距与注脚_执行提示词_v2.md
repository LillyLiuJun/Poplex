# Tab2 · More to talk about —— 间距与注脚优化 执行提示词 v2

> 背景：More 列表已上线，实机观感偏紧，且注脚一行内出现两处省略号。
> 本轮**只做减法和呼吸**，不改结构、不改图片裁切逻辑、不改数据契约。
> 依赖文档：`docs/prd/Tab2_More列表_设计方案_v1.md`

---

## 第 1 刀 · 间距（纯 Token 调整）

### 目标
让 More 列表的松弛感和整页一致。现在的问题不是字号，是**卡片之间比卡片内部还紧**，以及**四层信息等距堆叠成一堵墙**。

### 要做成什么样

改动全部落在 `AppTheme` 的 spacing token 上，不要在 View 里写散装数值。若 `AppTheme.Tab2MoreRow` 命名空间不存在，请新建。

| 维度 | 现状 | 目标 |
|---|---|---|
| 卡片之间的外间距 (rowGap) | 11 pt | **16 pt** |
| 卡片上下内边距 (padding Y) | 12 pt | **16 pt** |
| 分类行 → 主句 | 4 pt | **7 pt** |
| 主句 → 注脚 | 3 pt | **6 pt** |
| 主句行距 | 偏紧 | 见下方"行距"说明 |

关键判据：**卡片外间距必须大于卡片内边距的视觉权重**。现在 11 < 12，眼睛会把五张卡读成一整块；改成 16 之后每张卡才是独立单元。

### 行距的特殊处理（重要）

设计意图是"衬线主句行高约 1.45 倍"。SwiftUI 没有行高倍数，只有 `lineSpacing`（**加法**，且不随 Dynamic Type 缩放）。

要求：
- 用 `lineSpacing` 实现，基准值按 `.body`(17pt) 推算，约 **7 pt**
- 定义成 token，不要写死在 View 里
- **不要**为了精确倍数去用 `.system(size:)` 换算字号 —— 违反 `CLAUDE.md:178`，字体必须保持语义 TextStyle

### 明确不要做的
- 不要改缩略图的裁切/贴边逻辑（图片仍然上下满高贴左边缘），这是下一轮单独验证的改动
- 不要改任何字号、字重、颜色
- 不要改 section 之间的间距

## 第 2 刀 · 注脚只保留 moments

### 现状问题
注脚行同时渲染 `scene_detail` 和 `+N more moments`，例如：

```
Interpreting stoc… · +11 more mom…
```

一行里两处省略号，且 `scene_detail` 被截断后完全不可读，信息量为零却占满宽度。

### 要做成什么样

**More 列表的注脚行只渲染 `+N moments`，删除 `scene_detail` 及其分隔符 `·`。**

- 文案格式保持 `+11 more moments`（与现状一致）
- `N == 0` 时整行不渲染（不要留空行，让卡片自然变矮）
- 注脚行不应再出现任何截断

### 这一刀的设计理由（供你判断边界用，不必写进代码注释）
Hero 卡保留完整的 `scene_detail · +N more moments`，More 只保留 moments。
两者信息层数拉开（Hero 六层 / More 三层），层级关系才成立——More 现在读起来像"缩小版 Hero"，这是整页注意力分散的来源之一。

**Hero 卡的注脚不要动。**

## 验收

请在以下条件下各截一张图自查：

1. **标准字号（Large）**：五张卡应能明显看出彼此独立；注脚行只有 `+N moments`，无省略号
2. **XXXL**：主句换行后卡片应自然增高，不得出现文字裁切或注脚被挤压
3. **AX1**：布局不得破版（`minHeight` 的逃生阀应生效）
4. **纯单词卡片 / 无图片卡片**：间距规则同样适用，不得因为缺图产生塌陷

改完后请把改动的 token 名和数值列一份清单回给我。
