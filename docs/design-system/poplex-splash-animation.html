Poplex
A从图标长出来1000ms · 已定

起手就是图标里那个 P，位置、字号、颜色和 iOS 图标放大转场的最后一帧对齐—— 用户感觉不到"换了一个界面"。P 收到字标大小，其余字母顺次长出来， 墨点最后从 P 底下滑到词尾坐定。

加到 1 秒后，多出来的 160ms 没有摊到每个动作上（那只会显得迟钝）， 而是全部给了词写完之后的那一拍静止——Poplex 完整地待在屏幕上 100ms， 然后才淡出。这一拍是"名字被看清了"的时间。

B被读过一遍800ms

字标整体淡入后，墨点从左往右扫过词底，身后拖一道极浅的橙线，走到末尾停住变成句点。 像有人把这个词读了一遍——和产品"说出来"的核心动作同构。 代价：没有承接图标，起手是空的。

C什么都不表演560ms

字标淡入 + 上浮，墨点晚 180ms 落下，结束。没有任何"动画感"， 只是让画面不是硬切。看一百次也绝对不烦，因为根本没什么可看的。 最保险，也最没有记忆点。

0.00–0.20 Poplex 淡入 + 上浮 8px
0.18–0.30 墨点落下
0.42–0.56 淡出
速度

已定：A，1.0 秒。开屏动画唯一真正的功能不是"好看"，是把系统的图标放大转场和 App 第一屏缝起来， 让启动看着是一件连续的事。A 的第 0 帧就是图标的最后一帧。

B / C 保留在这里作为退路：如果哪天觉得 1 秒还是长，不要去压缩 A 的各段—— 压缩会毁掉那一拍静止，动作会变得急促。正确的退法是直接换成 C。

落地时要注意的三件事（写 SwiftUI 时会踩）：
① iOS 的 LaunchScreen 是静态的，动不了。所以真正的做法是： LaunchScreen 画一张和动画第 0 帧一模一样的静态图（纸底 + 居中的大 P）， 动画在第一个 SwiftUI View 里播。两者对不齐就会闪一下。
② 动画期间要并行做启动初始化（Supabase session、字体、首屏取数）。 如果数据先到，动画照播完；如果动画播完数据还没到，直接进 Tab1 的 loading 态， 绝不因为动画而多等。
③ 关掉动画的开关要有：系统「减弱动态效果」（UIAccessibility.isReduceMotionEnabled） 打开时，直接用 C 方案的纯淡入。
