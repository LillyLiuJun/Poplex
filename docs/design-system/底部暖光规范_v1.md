# 底部暖光 · 全局设计规范 v1

> 这套参数已经调过四轮。本文档的目的是把「谁该有暖光、用哪种形式、参数从哪来」写死，
> 让以后新页面查表即可，不再逐次讨论。

---

## 一、两份方案的异同

**结论一致的部分**（不再论证）

- Tab2 的暖光过大过浓，必须收
- Settings / Feedback / How AI uses your data 保持无暖光是**对的**，不是遗漏
- 解锁前的状态需要单独处理

**对方更具体、已采纳的两点**

- 460pt 的椭圆宽度**超过了 iPhone 16 Pro（393pt）乃至 Pro Max（440pt）的屏宽**。
  这意味着横向衰减根本看不见，它读起来是一条横贯的光带，不是一团局部的光。
  这是「显得大」最直接的几何原因，我之前只说了结构原因。
- 解锁前后应差异化。

**一处必须纠正的论证**

对方说「Tab2 的 0.22 是 Tab1 的 5.5% 的四倍浓度」。**这两个数不可直接比较**：

| | Tab1 背板 | Tab2 椭圆 |
|---|---|---|
| 颜色 | `inputBackdropWarmTint`（低饱和暖色） | `canvasAura` = `#FF7622`（品牌纯橙） |
| 几何 | 线性渐变，底部达到该色 100% | 径向渐变的**峰值** |
| 后处理 | 无 | **blur 44 + offsetY 下推** |

Tab2 那 0.22 经过 44pt 模糊再下推之后，落到屏幕上的实际浓度远低于 22%。

**照字面砍到 0.07 会重演一个已经犯过的错**：早前 `0.24 / 220 / offsetY 150` 的版本，
实测暖度差只有 **1.5/255**，等于完全没渲染。后来把 `offsetY` 从 150 收到 80 才让它可见 ——
**决定可见性的主要是几何（下推量），不是峰值透明度。**

所以本方案的杠杆放在几何上，透明度只做小幅回调。

## 二、为什么只有 Tab2 显得大：结构 + 几何

**结构**：同一团光，上面压着不透明控件时只看得到边缘漏出的一圈；裸露时看到的是全貌。

| 页面 | 暖光形式 | 上面盖着什么 |
|---|---|---|
| Tab1 | 输入框背板 | 52pt 输入胶囊 |
| Onboarding | 底部渐隐（改造后） | Continue 按钮 |
| **Tab2** | **独立椭圆** | **什么都没有** |

**几何**：460×260 的椭圆宽于屏幕，横向衰减不可见 → 读作光带而非光团。

**这个问题有一半会自动消失**：解锁前的 CTA 沉底后，Tab2 解锁前就变成「有底部常驻控件的页面」，
按下面的 A 档规则暖光归背板、椭圆删除。所以真正需要重新设计的只有**解锁后**。

## 三、三档规则（覆盖全 App）

判据是**页面身份**，不是「有没有控件」。三档互斥，C 档优先级最高。

### A 档 · 主场景 + 底部常驻控件 → 暖光归控件背板

**适用**：Tab1、Tab2 解锁前（CTA 沉底后）

> **Tab2 解锁前当前有意不给暖光**（`bottomScrimBackdrop` 是 100pt 纯纸色、零暖橙），
> 这是 2026-09 的决定，不是待办。三条理由：页面自身写着「Not open yet」，
> 按语义它不是「可以停留的地方」；解锁前后的暖度落差正是解锁动作的回报，
> 提前给了就没有兑现感（解锁本来有 `unlockDissolve` 转场吸收落差）；
> 且线性背板的暖橙铺在底部会被贴底 CTA 与 Home 条挡死，改了也看不见
> （Onboarding 已验证过这条）。

- 形式：线性渐变背板（`clear → pageBg` + `inputBackdropWarmTint` 补偿层）
- 参照实现：`WarmGlassBar.swift`
- 暖橙浓度：`inputBackdropWarmTint`，当前 5.5%
- **不画椭圆**

#### ⚠️ A 档例外 · Onboarding 各屏 → 背景层椭圆

Onboarding 曾按上面的背板配方做过一版，实测不成立，已于 2026-09 改回背景层椭圆并定稿。

- 实现：`OnboardingShared.swift` 的 `OnboardingAuraBackground`
  （`RadialGradient` 2 档 `canvasAura.opacity(0.20) → clear`、`endRadius 220`、
  frame `460×260`、`blur 44`、`offsetY 40`，挂 `.overlay(alignment: .bottom)`）
- 配套：`OnboardingBottomFade` 是 **130pt 纯纸色、零暖橙**——它在内容之上，任何暖色叠加会染照片和卡片
- **为什么背板配方在这里不成立**：本页要的观感是「一团浮在 CTA 上方的光」，它有横向衰减；
  线性渐变在水平方向恒定，物理上做不出来。实测（iPhone 16 Pro，距屏底 131pt 行）：
  中线 R−B = 41、屏幕边缘 = 14.6、纸色基线 = 9（旧页面底 #FCF8F3 时期实测），**中线比边缘暖 26/255**
- **椭圆下半部被 130pt 纸雾压白是特性不是 bug**：削掉之后可见峰值才浮到 CTA 上方约 130pt、
  屏底 45pt 收成干净纸色。曾有一版把这当缺陷「修复」成纯背板，结果暖度全堆在屏底、
  被按钮和 Home 条挡死，页面上几乎没有光

> 这条例外只适用 Onboarding。Tab1 仍走背板，两套参数不要互相套用。

### B 档 · 主场景 + 无底部常驻控件 → 内容收尾的一抹微光

**适用**：只有 Tab2 解锁后

它是「读完了」的句号，不是光源。

**已定稿**（`BottomAuraFooter.swift` / `WarmAuraGlow.swift`，方案 3D 实测验收通过）：
宽 320 / 高 102（等比压制比 `scaleY = 0.32`）/ `offsetY 60` / 峰值 `0.11` / `blur 20`。
采用 Circle 等比压制几何模型，从源头彻底消灭了旧版「正圆径向渐变遭扁椭圆硬裁切」导致的内外双层光圈缺陷。
挂在**滚动内容**的 `.background(alignment: .bottom)`，随列表滚动，不是全页固定。
配套排版与留白：双行纯文字极简弱化暖灰（字标 12.5pt `textMuted` + 标语 10.5pt `textMuted.opacity(0.85)`，行距 6pt），上留白 72pt (`tab2FooterTop`)，底留白 52pt (`tab2FooterBottom`)。

#### 「比 A 档更收」指的是覆盖范围，不是峰值

这条以前写作「参数必须比 A 档更收」，容易被误读成峰值要更低。实测不是这样，
定稿时也确认过当前观感可接受：

| | 中线峰值 | 峰值位置 | 屏幕边缘 | 纵向影响范围 |
|---|---|---|---|---|
| A 档例外（Onboarding） | +32 | 距屏底 131pt | +5.5 | 约 260pt |
| B 档（Tab2 解锁后） | **+25** | 距屏底 20~40pt | **+1.0** | 约 90pt |

峰值只差 22%，**但 B 档的光团明显更窄、更短**：两侧基本归零（+1 对 +5.5），
纵向影响范围只有 A 档的三分之一。收敛体现在**这团光占多大地方**，不在它最亮处多亮。

#### 验收标准（实测，不是参数值）

**必须写明取样列**。以 iPhone 16 Pro、滑到列表底部、纸色基线 R−B ≈ 6 为准
（2026-10-08 页面底改为 #FBF8F5 后的基线；此前 #FCF8F3 时为 8~9。下表是「相对基线的爬升」，不受基线变化影响），
下面是定稿时的实测值，重调后应落在各值 ±20% 以内：

| 取样点 | 相对基线爬升 |
|---|---|
| 中线（x≈201pt）· 距屏底 20~40pt | **+25** |
| 距屏底 30pt 行 · x=105pt | +15 |
| 距屏底 30pt 行 · x=55pt | +5 |
| 距屏底 30pt 行 · 边缘 x=5pt | +1 |

> ⚠️ **旧版本写的「4~6/255」已作废，不要再用。**它没有记录取样列，而同一张图上
> 中线读 +25、x=55pt 读 +5.0 —— 整个争议区间都在一张图里，这个数字无法判定对错。
> 这正是本文档「踩过的坑」里第 2 条的实例。

> ⚠️ **在当前配置下 `offsetY` 已经不是可见性的主开关。**
> 实算 `offsetY` 90 / 110 / 130，中线峰值 29.7 / 29.8 / 29.1 几乎不动，只是把峰值位置推到贴屏底
> —— 椭圆已经够低，44pt 模糊把它整个摊开了。早前 150→80 那次之所以有效，是因为当时椭圆
> 几乎整颗在屏外。**要改强度就改浓度**；本文档开头那条「杠杆在几何不在透明度」只适用于
> 椭圆大部分在屏外的情形。

### C 档 · 工具层 / Sheet → 不要暖光

**适用**：Settings、Feedback、How AI uses your data，以及未来所有从下方升起的抽屉

**这不是遗漏，是设计。** 这三个页面共用 `SettingsScreen` 外壳，从下方升起，
是办完事就关掉的临时层，不是「可以停留的地方」。

在这套语言里，**暖光标记的是「主场景」**：
有暖光 = 你在主场景；没有 = 你在一个临时层。**没有暖光本身就是信息。**

给抽屉也加暖光会有两个坏处：削弱它作为临时层的身份；与它背后那一层的暖光叠加。

**C 档优先级高于 A 档。** Feedback 页底部有发送按钮，按 A 档「有常驻控件」似乎该有背板暖光 ——
**不该**。判据是页面身份，不是控件的有无，否则两条规则会打架。

若发送按钮确实需要承托（防止内容硬顶在按钮下面），只给 **Layer 1 的纸色渐隐，不加暖橙**。
功能问题解决，身份保持。

## 五、一句话规则

> **暖光标记「这是一个可以停留的地方」。**
> 有底部常驻控件的主场景，暖光藏在控件背板里；
> 没有的，画一抹收尾微光；
> 临时抽屉，一概不给。
