## 一、一句话看懂整个架构

**Tab1 的意义是输入生成内容，Tab2 的意义是让用户练习和成长。**

这不是"同一批内容的两种看法"，是**两个功能阶段**：Tab1 进料，Tab2 加工和产出。

```
Tab1 · 输入生成              Tab2 · 练习与成长
  用户说一段生活              把素材变成"我能说出口的"
  AI 生成学习内容      ──▶    ├─ 练什么：词条账本（练习清单）
  素材落库                    ├─ 怎么练：对话页（练习执行）
                              └─ 练得怎样：成长层（练习结果）
```

**对话页不是第三个并列的 Tab，它是 Tab2 的练习执行页**——从 Tab2 发起，练完回 Tab2。

**判断任何新功能该放哪，只问一句：它是在"造素材"还是在"把素材变成能力"。** 前者归 Tab1，后者归 Tab2。

> **对照 `CLAUDE.md`**：这与项目最初定义完全一致——"Tab1 does NOT handle categorization or practice"、"Tab2 … also hosts the practice feature"。本文档不是新框架，是把它执行到底。

## 二、Tab2 的三层：练什么 / 怎么练 / 练得怎样

Tab2 的意义是练习和成长，所以它的一切结构都要能回答这三个问题。

### 2.1 练什么 —— 词条账本是练习清单

**练习的单位是"一个表达"，不是"一段经历"。** 你要练的是把某个说法说出口；场景是练习的**语境**，不是练习的**对象**。这是 Tab2 以词条为中心的根本理由。

- 主列表 = **词条列表**（跨所有输入聚合、去重后的账本）。
- 点一个词 → 看到它在你哪些场景里出现过 —— **这是在告诉你"该在什么处境下把它用出来"**，是练习的语境供给。
- "词条"是泛化的表达单元：单词 / 短语 / 词伙 / 俚语 / 习语 / 固定句型（`entry_kind` 区分）。
- 想**整段回看一件事**（"帮妈妈弄手机"那次说了什么）→ 去 Tab1，那里完整保留。Tab2 不重复提供。

**硬约束：每一行必须带练习状态。**

```
set up          phr.   ● 说过 3 次      家庭
run late        phr.   ○ 还没说过        工作
invoice          n.    ○ 还没说过        工作
```

`○ 还没说过` 不是装饰，**它就是练习进度**——一个练习清单必须让人一眼看到"哪些还没练"。这也正是 `Tab2_PRD` 第一节要的"让他看见差距，并推他去补上"。

> 数据来源是 `spoken_count`，而 `spoken_count` **只有对话页会写**。这决定了施工顺序（第五节）。

**筛选 = 一个列表 + 顶部一排镜头标签**（不是把页面切块）：
`For review`（默认，策展现在该练的）· `All` · `Not yet` · `Spoken` · `Recent` · `By scene`（展开复用现有情境 chips）

### 2.2 怎么练 —— 对话页是练习执行页

- **独立页面，从 Tab2 发起**（词 → 来源场景 → "和它聊聊"），**不作主屏默认页**。像语音通话：从别处进入、沉浸、结束退出。
- **语音形态**（MVP 无文本聊天模式）。
- 结束产出一张**总结卡**：这次用出了哪些你的词 / 待提高 / 进步（三块条件展示，没有就不显示）。
- 对话中 **AI 绝不打断、不纠错**；纠正只在总结卡里以「也可以这么说」的口气给 1–2 条。
- 对话产出的值得留存的内容，**用户确认才入素材库**。

> **文档缺口（必须补）**：`Tab2_PRD_v1` §4 写着卡片状态与练习机制"已拆分到《Tab2_卡片状态与练习机制_v1.md》"，**该文件在仓库中不存在**。Agent PRD 的"对话陪练"事实上填了这个位置，但两边从未挂钩。**需明确写下：对话页 = Tab2 的练习功能，不存在另一个待设计的练习模块。**

### 2.3 练得怎样 —— 成长层是练习结果

- 读账本 + 读用户实际说出来的话，做差距分析：正向（长出新东西）/ 负向（有词没用起来、反复的错、语法薄弱点）。
- **只陈述现状、不评价、不打分**（硬原则）。
- 入口：Tab2 里一个安静的入口 + 周期性推到首页 + 对话总结卡带链接。**不做第三个底部 Tab**。

## 三、Tab1 · 输入生成（**本轮不动**，此节只写目标）

### 3.1 现状（本轮保持）

对话流：用户气泡 + AI 卡片 + 日期分隔符交替排列，底部输入框。历史全部保留。

### 3.2 未来目标形态

| | 现在 | 目标 |
|---|---|---|
| 首屏 | 对话流（气泡 + 卡片交替） | **纯浏览态的内容库**：只有卡片，按时间排列 |
| 输入 | 首屏底部常驻输入框 | 首屏底部只留**一个入口条**；点开进入**全屏独立输入态** |
| 输入态 | 无 | 自带引导（建议 chips）、附件 / 相机 / 语音、历史入口、关闭 |
| 一次输入 | 一个气泡 + 一张卡 | **一张卡**（输入即生成，非往复对话） |
| 历史 | 全部保留 | 全部保留（不变） |

**这个形态的三个结构含义**（后续设计要接住）：

1. **输入态是新用户引导的家。** 现在的"新用户态 / 快捷示例 / 破冰引导"应该落在输入态的建议 chips 上，而不是首屏。
2. **输入时首屏不可见。** 用户写的时候看不到已有内容，所以"参考我以前说过的"必须由输入态自己提供（历史入口），不能指望用户翻列表。
3. **首屏不是生成的副产物列表，它就是"我的内容库"。** 生成是一个动作，不是一个页面。

### 3.3 边界（Tab1 不做什么）

- **不做分类整理**（`CLAUDE.md`）——异步进行，用户手动切 Tab 才看到结果。
- **不做练习入口**（`Tab2_PRD_v1`）——练习统一从 Tab2 发起。
- **不做往复对话**——那是对话页。Tab1 只负责"输入即生成"。

> **随之作废**：`Agent内容组织与成长系统_PRD_v1` §6.2 的"冷起手住 Tab1"。Tab1 结构上不做往复对话，无 seed 的自由起手需重新安置（待定-2）。

## 四、数据关系：账本是交汇点

```
        Tab1 输入                       对话页（Tab2 的练习执行）
     （一次输入一张卡）                    （一来一回说出来）
            │                                    │
            │          两个入口都往账本记账          │
            ▼                                    ▼
   ╔═════════════════════════════════════════════════════╗
   ║  词汇账本 lexicon = Tab2 的练习清单                    ║
   ║    lexicon_entries      去重后的词条（练什么）          ║
   ║    lexicon_occurrences  每次使用的流水（练习证据）      ║
   ║    learning_events      弱点 / 错误 / 进步（练习节点）  ║
   ╚═════════════════════════════════════════════════════╝
                              │
                              ▼
                        成长层（练得怎样）
```

三张表的字段设计见 `Agent内容组织与成长系统_PRD_v1` §5.4，本文档不重复。
`materials` / `messages` 两张表**结构不变**，账本是并行长出来的一层，不是替换。

## 五、施工顺序

排序原则：**每一步都不能让线上功能净减少。**

| 阶段 | 做什么 | 为什么是这个顺序 |
|---|---|---|
| **一** | 账本只写不读：`generate` 新增记账，两张表开始积累数据 | 账本要先有数据，Tab2 才有东西可换。前端零变化，风险最低 |
| **二** | 对话页上线（含 `spoken_count` 写入） | **必须早于 Tab2 换主体**——`Not yet` / `Spoken` / `For review` 三个镜头全依赖它，没有它 Tab2 换过去会有一半标签是死的 |
| **三** | Tab2 换成词条主视图（练习清单 + 练习状态） | 此时账本有数据、状态有来源，换过去立刻是完整可用的 |
| **四** | 成长层 | 依赖前面全部 |
| **—** | ~~Tab1 改形态~~ | **本轮不做**。独立于以上全部，将来任何时候可单独排 |

> **这是对原 Agent PRD 排期的修正。** 原排期把"Tab2 换主体"放在对话层之前（Slice 3 早于 Slice 4-6），会交付一个六个镜头里三个是死的界面，同时砍掉现有的场景浏览和词汇本——净负收益。调换后每一步都是净增。

## 七、确定 / 修正 / 待定

### 已确定

1. **Tab1 = 输入生成内容；Tab2 = 让用户练习和成长。** 按功能阶段划分，不按索引方式划分。
2. **对话页 = Tab2 的练习执行页**，不是第三个并列的面；从 Tab2 发起、不作主屏。
3. Tab2 三层结构：练什么（词条账本）/ 怎么练（对话页）/ 练得怎样（成长层）。
4. Tab2 以词条为中心 —— 因为**练习的单位是表达**；场景是练习语境，整段回看归 Tab1。
5. **词条行必须带练习状态**（`○ 还没说过` / `● 说过 N 次`）。
6. 施工顺序：账本写入 → 对话页 → Tab2 换主体 → 成长层。**Tab1 本轮不动。**

### 修正了先前文档的判断

| 先前的说法 | 出处 | 修正为 |
|---|---|---|
| "三个承载面按**组织单位**并列划分" | 本文档 v1 | **撤销**。按**功能阶段**划分；对话页是 Tab2 的下级页，不与两个 Tab 并列 |
| "Tab2 以场景为主、账本作第二镜头" | `Agent系统PRD_逻辑审查_v1` 待-1 | **撤销**。Tab2 以词条为中心成立，理由是练习单位是表达 |
