# 商店图五层框架

```
┌──────────────────────────────────────────────┐
│  1. 文案层：超大主标 + 1句副标（价值/场景，非功能）│
├──────────────────────────────────────────────┤
│  2. 破框层：核心卡片/气泡悬浮放大（打破设备约束） │
├──────────────────────────────────────────────┤
│  3. 设备层：钛金属微壳 / 无边框屏幕 / 微倾斜视角  │
├──────────────────────────────────────────────┤
│  4. 光影层：环境微阴影 / 局部投影 / 底部漫反射光   │
├──────────────────────────────────────────────┤
│  5. 背景层：连版跨屏 / 暖纸肌理 / 弥散渐变 / 品牌色 │
└──────────────────────────────────────────────┘
```

每张图都按这五层从上到下检查。每层先定**全套统一的规则**，再定**单张的变化**。

## 一、工作流程

1. **定位**：先弄清这套图要讲的故事。一张图只讲一件事，整套按「是什么 → 怎么用 → 得到什么 → 为什么信」排顺序。
2. **逐层定全套规则**：从文案到背景，每层给 2–3 个方案并排对比（在 Figma 里并排做出来），用户选定后写进规范。
3. **单张精修**：先把每张调到满意，再做全套对齐。
4. **素材**：需要真实界面时，写 prompt 让模拟器 / 开发 agent 造数据并截图，不手画假界面。
5. **全套对齐**：五张并排检查尺寸、边距、字号、阴影、数据是否一致。
6. **导出**：1320×2868（6.9 寸）@3x，导出前隐藏标注层。

协作习惯：

- 用户说「先理解需求」时，只复述理解、给出草拟数据和待确认点，不动手。
- 说话简短，方案用表格对比，标明推荐和理由；被说「太复杂」就收缩。
- 新方案放新的 section / frame，不覆盖用户的定稿区。
- 写完再截图核对，不和写操作并行；截图像旧的就重截。

## 二、逐层要点

### 1. 文案层

- **主标**：超大、两行以内，讲价值或场景，不讲功能名。要**直接**：让人一眼知道「我做什么、得到什么」，避免抽象口号。
- **副标**：一句，补充主标没说的那一半（如另一个方向、具体结果），不重复主标。
- 三拍句式（如 Snap it. Type it. ___ it.）的最后一拍要落到具体结果，不用含糊动词。
- 抽象词（好奇心、anything）要限定在产品的真实场景里，避免被读成别的品类。
- 整套检查：各图主标不要互相重复关键词；首图标签不重复首图主标或其他图的主标。

### 2. 破框层

两种取向，**全套只选一种**：

| 取向 | 做法 | 适合 |
|---|---|---|
| 张扬版 | 核心卡片/气泡放大、宽过屏幕、带重阴影浮出 | 首屏抓眼、单张主打 |
| 安静版 | 不破框，重点只靠屏幕内一处轻强调（浅品牌色底 + 细描边） | 追求高级、可信、整套统一 |

规则：

- 每张**只有一个**主角。两个元素同时破框、同等大小会互相抢。
- 破框元素必须是界面里真实存在的模块，放大后按原位对齐（原位放大）。
- 如果整套感觉「太张扬、凌乱」，优先撤掉破框，改成屏幕内高亮。
- 角度：全套最多一个元素倾斜，其他都摆正；多个方向的倾斜会显得乱。

### 3. 设备层

- 选一种设备样式贯穿全套：钛金属微壳 / 无边框屏幕（圆角 + 阴影）/ 微倾斜视角。
- 统一：屏幕宽度、左右边距、顶部 y、圆角、出血方式。推荐居中，左右边距相等，底部出血。
- 状态栏和导航栏在每张图里的高度要一致；不同尺寸的截图放进来，先缩放到统一宽度再定位。
- 不放第二台手机，不用整机倾斜（除非全套都这样）。

### 4. 光影层

- 全套只用一套阴影参数（如设备：0 2 6 /8% + 0 24 48 /16%）。
- 破框元素的投影可以略重，但要和设备阴影同一光源方向。
- 底部漫反射光、局部光晕要克制，全套同一位置、同一强度。

### 5. 背景层

- 选项：连版跨屏 / 暖纸肌理 / 弥散渐变 / 品牌色纯色。
- 先做全套对比（同五张、不同背景各一行）再定。
- 连版跨屏要检查每张单独看时是否也成立（商店里经常只露出前两三张）。
- 首图可以和后面不同（如品牌色），但要像同一个家族。

## 三、首图

两种方向，先和用户确认：

- **产品首图**：标题 + 真实界面，适合新 App 让人立刻看懂。
- **品牌封面**：logo + 大标题 + 副标 + 三个价值标签 + 底部信息（如语言方向），不放截图，重点是信任和品牌感。

品牌封面规则：

- 三个标签各回答一个不同问题（与众不同在哪 / 得到什么 / 为什么可信或有什么特色），不重复主标。
- 不用麦穗、奖章等奖项符号装饰非奖项内容。
- 用国旗表示语言有风险，优先用文字胶囊（如「中文 ⇄ English」）。

## 四、规范模板（定稿后填写）

| 项 | 规格 |
|---|---|
| 画布 | 440×956（1320×2868 的 1/3），导出 @3x |
| 主标 | y __ ｜字号 __ ｜行数 ≤ 2 ｜字体 __ |
| 副标 | y __ ｜字号 __ ｜行高 __ |
| 设备 | 宽 __ ｜左右各 __ ｜顶 y __ ｜圆角 __ ｜出血方式 |
| 阴影 | __ |
| 强调 | 每张一处，样式 __ |
| 背景 | __ |
| 禁止 | 列出本套不允许的做法 |

在 Figma 里放一个「规范」frame：以最标准的一张为底，加参考线和标注层，旁边写规范文字。

## 五、素材 prompt（给模拟器 / 开发 agent）

结构：

1. **约束**：只为商店图造数据和截图；不改正式代码、不提 PR；演示数据只走 DEBUG 注入，不写线上数据库；截图必须是真实渲染，不为截图新增或隐藏界面元素。
2. **这张图要表达什么**。
3. **与旧 prompt 冲突时以本文件为准**，列出差异。
4. **数据表**：时间、分组、输入、期望输出；数量类指标写「约 N」，要求真实累计。
5. 胶囊数量、+N、时间文案、排序等**以代码真实结果为准**，在汇报里说明。
6. **截图规格**：机型、浅色、默认字号、状态栏 9:41 满格满电、@3x、文件名、画面范围。
7. **汇报**：先描述画面实际内容再下结论；列出写入的数据；核对跨图一致性；说明 DEBUG 夹具位置；**汇报后停下等确认**。

## 六、一致性与审核风险

- 多张图里出现的同一数据（分类名、计数、词条）必须来自同一份数据，数字要对得上。
- 不要展示未上线的功能入口或按钮；若入画，确认当前版本可见且可用，否则有 App Review 以「截图与实际不符」拒审的风险。
- 不展示调试标记、空态、加载中、错误提示。
- 卡片上不显示的字段，不为截图加上去。

## 七、Figma 操作要点

- 使用 `use_figma` 前加载 figma-use skill。
- 插件里可能加载不到品牌字体（如 Charter）：用相近字体占位，最后由用户手动替换；带该字体的文本节点无法改字，把文案交给用户改。
- 放截图：`resize(目标宽, 原高×目标宽/原宽)`，统一 x / y / 圆角 / 阴影。
- 屏幕内强调做成单独图层，方便调整或关闭。
- 拼接截图用裁剪 frame + 同一张图偏移；拼缝处检查底色。
- 新 frame 间距 40px，标签放 frame 上方并设宽度，避免重叠。
- 脚本报错会整段回滚；先确认引用的节点 id 还在（用户常清理旧 frame）。

## 八、交付前自查

- [ ] 五层逐层过一遍，每层全套规则一致
- [ ] 每张只有一个主角 / 一处强调
- [ ] 设备尺寸、位置、圆角、阴影、状态栏高度全套一致
- [ ] 主标直接、不互相重复；副标补充而非重复
- [ ] 跨图数据一致；无未上线功能、调试标记、空态
- [ ] 标注层已隐藏，字体已替换
- [ ] 导出 1320×2868，五张并排做最后检查
