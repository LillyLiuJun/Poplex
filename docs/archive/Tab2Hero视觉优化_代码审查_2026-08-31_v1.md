## 2. 缺陷（按严重度排序，每条含可构造失败场景）

### 2.1 [中] `AppTheme.Font.cardMeta` 被本刀弄成孤儿 token，未随刀删除

`AIEnglishApp/Theme/Theme.swift:405`

本刀重做 HeroTopOverlay，删掉了 `cardMeta` 的**最后一个**消费者
（旧 pops 胶囊与 "+N more moments"），改由新 token `tab2HeroPopsLabel` /
`tab2HeroMeta` 承担。全分支 grep：除定义外零引用，且其注释仍写着
"卡片右上角 meta（Hero 卡 pops 数等）"——描述已过时。

CLAUDE.md token 卫生规则原文："Applies to tokens **your slice orphaned** —
if you removed the last consumer, remove the token in the same commit.
That is the rule."

失败场景：无运行时失败，但违反硬规则；下一个 token 体检轮次会把它当
"已退役决策"清理（若有人按其过时语义挪用还会误用）。修复 = 本刀删掉该行。

### 2.2 [低] Dynamic Type 下模式 D 词行与 CTA 固定高度裁剪

`AIEnglishApp/Theme/Theme.swift:709`（`artTextOverlap` 固定体系）、
`:714`（`ctaHeight = 42`）、`:739`（`wordRowHeight = 26`）

字体 token 全部基于系统 TextStyle（会随辅助功能字号放大），但承载它们的
高度是固定 pt 值。

可构造失败场景：系统设置 → 辅助功能 → 更大字体（AX1+）：
- 模式 D 三行词条（`tab2HeroWord` = subheadline）行高超过 26pt，
  三行垂直相互侵入；
- "Start talking" 在 42pt 胶囊内垂直溢出。

这与项目规则"Text 必须走 TextStyle token 以保留 Dynamic Type"的精神冲突
（字形放大但容器不随动）。静态审计能指出构造条件、不能替代真机观感，
建议真机走一遍更大字体档确认可接受度（MVP 阶段 PM 拍板接受即关）。

### 2.3 [低] `SceneCategory.momentIconName` 成为死代码

`AIEnglishApp/Utilities/SceneCategoryMap.swift:66`

唯一消费者（旧 `CategoryPresetArtView` 占位图）在本刀被 Path 插画替换，
属性与分支内无任何引用。属"删除共享 API 后跨文件残留"（审计模板列举的
跨文件语义断裂的反向情形）。无运行时失败；建议随刀删除或注释保留理由。

### 2.4 [低] `Tab2HeroCard.isFirstUnlock` 成为死参数

`AIEnglishApp/Mine/Components/Tab2HeroCard.swift:6`

重设计后 struct 内**零读取**（首解锁专属文案逻辑随旧布局一起删除），
但参数保留，调用方 `MineView` 仍传 `vm.isFirstUnlock`（View Model 侧该
状态仍活跃，供动效使用——死的是卡片侧参数）。无运行时失败；建议删除
卡片侧参数与 Preview 传参，避免后来者误以为首解锁文案仍生效。

### 2.5 [低] `otherUnlocked` 计算后未使用（编译警告）

`AIEnglishApp/Mine/MineView.swift:656`

`let otherUnlocked = data.categories.filter {...}` 计算后无任何读取
（TODO 注释说明有意保留计算）。产生 "initialization of immutable value
was never used" 警告。失败场景：若 CI 开启严格警告转错（Swift 6 语言模式
下部分警告会升错），构建可能失败——当前默认配置不会。建议改为
`_ = data.categories.filter {...}` 或暂时注释掉整段。

### 2.6 [低] 四个用途命名的 `tab2Hero*` 值进入 Primitive 层

`AIEnglishApp/Theme/Theme.swift:159-162`

`tab2HeroPresetGradientMiddle / tab2HeroPresetBloomSecondary /
tab2HeroPresetIcon / tab2HeroPresetLabel` 是组件私有色值，却以用途命名
放进 Primitive 层。按规则 4，组件私有值**恰好适用"语义层直接持原始值"的
例外**——应留在语义层（如 `tab2HeroPresetLabel = Color(hex: 0x8A4A20)`
直接写在语义层）；放 Primitive 把"调色板 scale"变成杂物抽屉，与规则 5
的 `progressBarHeight` 反例同构。无运行时影响，架构合规问题，建议下一轮
token 体检一并迁移。

## 3. 风格建议（构造不出失败场景，不混入缺陷）

1. **负 padding 实现图文重叠**（`Tab2HeroCard.swift:23-24`）：
   `.offset(y: -14)` + `.padding(.bottom, -14)` 双保险写法，负 padding
   属未文档化边角用法，未来系统版本行为变化风险。建议单用 offset 并显式
   扣减卡片总高。#Preview 已视觉验证，不改也可接受。
2. **`metaRow` 的 fixedSize/maxWidth 组合**（`Tab2HeroCard.swift` 约
   93-105 行）：依赖 `fixedSize(horizontal:true)` 与 `frame(maxWidth:175)`
   的布局顺序细节实现"短标签不占位、长标签截断"。已有注释说明，Preview
   已视觉验证；若后续出布局回归，优先怀疑此组合。
3. **三个 UserDefaults 数组无界增长**：`spokenMoments` /
   `heroKnownMoments` / `heroKnownSpokenMoments` 每遇新 scene_detail 变体
   永久 +1，配合已知的 scene_detail 未归并问题（优化需求清单），长期膨胀。
   MVP 可接受，建议记入待迭代。
4. **milestone 边界上稳定缓存无效化**：milestone 分类被 `excluding` 排除
   时其 moments 不写入 `heroKnownMoments`；milestone 清除后这些 moments
   被视作"新 moment"触发重算，hero 可能来回切换。与旧代码（每次重算）
   行为等价、非回归，仅缓存机制在该场景下失效，备注即可。

- **scene_detail 双端校验一致**：后端 `TARGET_SCRIPT = /^[A-Za-z][A-Za-z\s'\-]*$/`
  （先 trim 再校验、截 24 字符）+ 客户端 `validatedTargetSceneDetail`

  → featured 无图时即使分类有照片也走预设图，避免图文错配 ✅（Preview 有对应用例）。

- **本地 Supabase 重放与权限矩阵**：委托方已自述验证（空库重放全部 migration、
