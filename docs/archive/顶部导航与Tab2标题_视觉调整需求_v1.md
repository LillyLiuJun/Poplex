# 顶部导航与 Tab2 标题视觉调整需求 v1

日期：2026-08-30  
状态：需求整理；未修改 App。视觉方向来自本次讨论，具体参数建议需在原生预览中验证。  
适用：Today / Library 共用顶部导航，以及 Library 已解锁首页标题区。

## 1. 目标与范围

减轻导航的底色、图标和容器重量；用居中的文字双 Tab 建立明确的页面切换入口。保留现有内容滚动、渐变遮罩、左右切换及其手势边界，不因视觉调整改动业务行为。

本轮只调整：

- Today / Library 从图标切换器改成两个独立文字入口，整体居中。
- 选中底纹比 HTML v2 更轻。
- 左侧实心人物图标改为轻量两条横线，仍打开原 Settings。
- Library 已解锁页采用已选定的 B 方案标题。

不调整：学习卡内部、输入框、主题卡与列表、业务状态机、数据加载、刷新、练习入口行为、Onboarding、Toast、全局字体家族。页面的产品职责不变。

## 2. 依据与优先级

1. 用户最新要求：底纹更轻、左侧用两条线、其他交互不变，特别保留上滑渐变遮罩及左右切换。
2. 上一轮已确定：仅保留 Today / Library 文字、两项分离、居中、只给选中项加底纹。
3. 已选定的 Tab2 B 方案：保留减轻后的 `Talk about today`，删除介绍副标题及重复的 `Your topics`。
4. 原生代码负责说明当前交互事实。HTML 与生成图仅供视觉参考，不是交互实现的权威来源。

参考：[文字导航 HTML v2](tab-navigation-study-v2.html)。

**对原型的明确修正：** HTML v1 / v2 的实色顶栏承托不作为开发要求。不得照搬为原生不透明横条；以现有 `TopBarProgressiveMask` 为准。v2 当前默认选中底纹为近黑 5.5% 透明度，用户认为偏重，不能直接作为最终值。

## 3. 导航结构

```text
屏幕左侧                         屏幕水平中心
两条横线设置入口                Today    Library
44pt 以上点击区域                只有选中项有浅底纹
```

- 左侧入口位置保持，不改成新侧边栏或抽屉菜单。
- 两个 Tab 的整体中心对齐屏幕中心，不对齐“设置按钮右边剩余空间”的中心。
- Today 在左，Library 在右；没有太阳、书本或其他替代图标。
- 两项之间有明确空隙；没有共同的外层胶囊、描边或阴影。
- 点击切换时，名称的位置和占用宽度保持稳定，不因选中而挤动另一个名称。
- 使用产品 UI 字体，不引入新字体。Tab 字重可通过对应语义 token 调整，不能借本轮修改所有正文。

## 4. 选中态与底纹

### 已确定

- 选中项：深色文字 + 极浅中性底纹。
- 未选中项：透明背景，无底纹；文字仍然清楚可读。
- 不使用品牌橙填充、暖米色实心块、重阴影或高亮白描边。
- 底纹属于单个 Tab，不形成围住两项的容器。
- 底纹变轻不能以文字变淡为代价。

### 建议起点，非已验收参数

| 项目 | 建议 | 理由 |
|---|---|---|
| 选中底纹 | 暖近黑约 3% 透明度；原生预览可比较 2.5% / 3.5% | 比 v2 的 5.5% 明显减轻，避免另加一块暖纸色 |
| 阴影、描边 | 不添加 | 层级交给轻底纹与文字 |
| 字体 | 先复用 `AppTheme.Font.tabLabel` | 本轮先解决布局与重量，保留 Dynamic Type |
| 单项点击区域 | 最小 44 × 44pt | 图形减轻，操作面积不缩小 |
| 两项间距 | 先用现有 8pt 间距档 | 两项分开但仍读作一组 |
| 底纹形状 | 沿用 v2 的单项圆角底，微调由原生预览决定 | 用户反对共同容器，未要求此处变为直角 |

底纹是在现有渐变材质之上显示的状态层，必须同时看静止底色、照片经过和文字经过三种情况；不能只在纯色 HTML 上决定最终透明度。

## 5. 左侧设置入口

- 将实心人物换为两条水平线，以降低视觉重量。
- 两条线等长、居中、圆端，作为首版实现建议；不添加第三条线或实心人物背景。
- 优先使用适配目标系统的原生符号；如采用自定义图形，应独立封装并使用主题尺寸、线宽和颜色，不在页面中散写绘制参数。
- 建议图形宽约 18–20pt，细线约 1.5pt；具体按原生渲染清晰度校准。
- 不增加明显的圆形底、外圈或重阴影；按压仍有反馈。
- 点击仍打开当前 Settings sheet，内容、关闭方式、返回行为不变。
- VoiceOver 名称为 `Settings`，不得读成“two lines”或暗示新增菜单功能。

## 6. 必须保留的交互

### 6.1 上滑渐变遮罩

- 保留 `AIEnglishApp/Components/WarmGlassBar.swift` 中 `TopBarProgressiveMask` 的材质、渐变节点和与安全区的关系。
- 保留内容从导航背后经过时的渐进模糊与消隐。
- 不替换为通栏实色背景、突然截断、硬分割线或新增厚重雾带。
- 不改变 Tab1 底部输入区的渐变托底。
- 居中实现若改变顶栏布局，必须核对顶栏实际高度传递及内容避让，防止间接拉伸、压缩遮罩。

### 6.2 点击与左右切换

- 点击 Today / Library 切换页面，保留原有状态更新与动画节奏。
- Today 左滑进入 Library；Library 右滑返回 Today。
- 保留当前水平意图判断和位移 / 惯性阈值，不因导航改造重新设计手势。
- Tab2 横向卡片轮播区域不触发全局切 Tab。
- 已展开滑动操作时的拦截与复位规则不变。
- Tab2 详情页的手势与顶部导航隐藏规则不变。
- 保留两个 Tab 的视图存续、滚动位置处理、切换到 Library 的现有刷新 / 复位行为；不改为重建页面。
- 不增设底部 TabBar，不改变初始 Tab，不引入新侧边栏。

### 6.3 原“滚动后收字”的必要例外

当前代码：只有选中项显示文字；Today 在 iOS 18+ 滚动超过 40pt 后只保留图标，回到 8pt 以内恢复，切 Tab 也会恢复。大号辅助字号下原实现也会仅保留图标。

新方向删除了全部 Tab 图标，因此**两个名称必须始终可见**，不能继续套用隐藏文字逻辑，也不能滚动后重新出现太阳和书本。这是“纯文字双 Tab”带来的必要调整，不影响渐变遮罩与左右切换。

在大号字体下，同样不得把文字隐藏为不存在的图标。优先保留字号增长、点击区域和完整名称；可通过响应式布局增加导航高度。若最极端字号必须采用独立导航行避让左侧入口，应作为可访问性布局验证，不得压缩整个页面或裁掉文字。

## 7. Library 标题区

- 已解锁首页仅保留 `Talk about today`，维持衬线方向，减轻原大标题的尺寸 / 字重。
- 删除 `Built from your daily moments.`。
- 删除卡片前重复的 `Your topics`。
- 保留 `Topics in progress` 以及下方主题列表。
- 第一张主题卡提前进入视野，标题与卡片维持清楚的组间距离。
- 原生字号和间距需要实屏确认，生成图不能作为精确尺寸依据。
- 未解锁、空白、加载、错误状态继续使用原有内容与流程，只适配共用导航；不直接套用已解锁标题。

## 8. 状态与可访问性

| 状态 | 预期 |
|---|---|
| 默认 / 未选中 | 名称可见、背景透明、可以点击 |
| 选中 | 名称位置不变，出现极浅底纹，读屏声明已选中 |
| 按压 | 轻量视觉反馈，沿用现有反馈方式；不新增明显弹跳 |
| 焦点 | 系统键盘 / 辅助操作可识别焦点，不用细底纹代替焦点提示 |
| 悬停 | 触屏非核心；指针设备使用平台标准反馈，不新增独立设计 |
| 禁用 | 本轮不新增 Tab 禁用态 |
| 加载 | 页面照常加载，导航仍可用；不把 Tab 文字换成转圈 |
| 错误 | 沿用页面原有错误 / 重试处理，导航本身不显示错误色 |

补充要求：减少动态效果设置下保持功能完整；文字与背景对比度需验证；两条线入口需验证非文字对比度；最低点击区域、大字号和设置入口避让必须实测。

## 9. 主题 token 与开发边界

| 用途 | 处理 |
|---|---|
| Tab 字体 | 优先复用 `AppTheme.Font.tabLabel` |
| 主 / 次文字 | 复用 `AppTheme.Color.textPrimary` / `textSecondary` |
| 点击区域 | 复用 `AppTheme.Size.barControl` 并保证至少 44pt |
| 页面侧边距、Tab 间隔 | 复用 `AppTheme.Space.paddingPage` / `paddingS` |
| 选中底纹 | 先检查是否有合适的浅底 token；现有 `pillNeutralBg` 为 6%，不可全局改浅以满足这一个组件 |
| 如需独立选中底 token | 建议语义 `color-navigation-tab-selected`，映射到 Theme 中的导航专用字段；最终命名遵循项目格式 |
| 图形参数 | 若现有语义 token 不适配，集中定义图标尺寸 / 线宽，不在组件中写魔法数 |
| 动画 | 保留 `AppTheme.Motion.tabSelection` 和现有页面切换行为；不重做全局动画 |

预计涉及 `Navigation/TopTabSelector.swift`、`Navigation/RootTabContainer.swift`、`Theme/Theme.swift` 和 Library 标题区。为删除已废弃的收字行为，可最小范围清理相关状态连线；不得顺带重构 Today 滚动、数据层或输入逻辑。

- [ ] 两个 Tab 无图标、无共同外框；名称完整，组中心对齐屏幕中心。
- [ ] 切换前后两项位置稳定，且只有选中项有底纹。
- [ ] 选中底纹比 HTML v2 更轻，不加选中阴影。
- [ ] 左侧为两条轻量横线，点击区域未缩小，仍打开原 Settings。
- [ ] Today 与 Library 滚动后均保留文字，点击切换正常。
- [ ] 上滑的渐变遮罩与修改前对照，无新增不透明顶栏、硬截断或突变。
- [ ] 实际左右滑动切 Tab 正常，卡片横滑不误触，详情页 / 滑动操作边界不退化。
- [ ] 输入框、键盘出现、下拉刷新、图片预览、Settings 展示与关闭不受影响。
- [ ] 已解锁标题采用 B 方案；加载、空、错误、未解锁状态没有内容重叠。
- [ ] 小屏、常用字号及辅助大字号下，无图标入口与文字互相覆盖，无页面横移、裁字。
- [ ] 至少记录 Today 顶部 / 滚动、Library 顶部 / 滚动四张原生截图，并实际演示切换动画。

本文件是需求与验收计划，不代表上述测试已运行或通过。实施后按项目节奏报告结果，再推进下一项视觉规范。

## 11. 使用的 skill 与适配说明

本轮使用 design-component 的组件结构、状态、token 映射与可访问性框架。安装目录目前只有 SKILL.md，未提供其引用的通用组件库、检查脚本与辅助文档，因此以项目 AGENTS.md、原生代码和本次用户决策为准；没有运行或声称通过 skill 的网页检查脚本。

SwiftUI 实施优先使用 swiftui-layout-components，动画回归使用 swiftui-animation；反馈文案另用 ux-writing。通用 Web ARIA / Lucide 实现建议不替代原生 SwiftUI 的可访问性与平台符号。
