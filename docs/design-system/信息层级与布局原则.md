# 信息层级与布局原则

> 做任何界面设计、调整或评审之前先读这份。它是产品负责人在实践中总结出来的诊断方法：
> 设计出问题，几乎都能归到**信息层级**或**信息布局**其中之一。
> 颜色数值以 `AIEnglishApp/Theme/Theme.swift` 为准；token 命名与复用规则见 [`token-rules.md`](token-rules.md)。

---

## 一、先分清是哪一类问题

| 问题类型 | 一句话 | 典型症状 |
|---|---|---|
| **信息层级** | 信息的**颗粒度**没有对齐 | 一个区块里，微观的东西和中观的东西并排或叠放，看起来乱 |
| **信息布局** | 位置、间距、强弱的关系没处理好 | 对不齐、风格忽左忽右、相关的东西离得远、该突出的不突出 |

先判断属于哪一类，再动手。判断错了，改再多也是在错的地方使劲。

## 二、信息层级：颗粒度要对齐

- 同一个区块里的信息，应处在**同一颗粒度**。
- 不要用微观颗粒度（一个词的标注、一个小图标）去和中观颗粒度（一张卡片、一整段内容）并排搭配。
- 做法：改之前先把页面上的信息按颗粒度分层列出来（宏观：页面 / 区域；中观：卡片 / 列表行；微观：词、图标、标注），检查每个区块里是不是混了层。

## 三、信息布局：四个原则

1. **对齐（Alignment）**：每个元素都和页面上另一个元素有视觉联系，边缘、基线对齐。
2. **重复（Repetition）**：同一语义用同一种样式；样式的重复建立一致性和识别度。
3. **亲密（Proximity）**：相关的内容靠近，不相关的内容分开；间距本身就在传达关系。
4. **对比（Contrast）**：要区分的东西就要明显不同；差别太小反而显得是失误。

## 四、用「物理形容词」描述和诊断问题

设计的感受和物理世界的感知相似。

- **低维形容词**：松 / 紧、大 / 小、轻 / 重、粗 / 细、疏 / 密、亮 / 暗。
- **高维感受**（高级感、舒服、有秩序、廉价感）是由低维形容词**组合**出来的，不是单独存在的。
- 好设计是**有秩序**的，让人感到真实空间里的**平衡**：
  - 颗粒度不一致，像衣服乱丢在地上；
  - 松紧不一致，像空间里东西疏密失衡，人会不舒服。

所以评审和描述问题时，**用低维物理语言**，不用「不好看」「不高级」这类品味词：

- 好：「这一块比上一块紧一档，而且标题和正文一样重」
- 不好：「这里感觉不太高级」

## 五、控制变量法（微观）

目的：能**真正定位**视觉问题，并能看出这次改动是不是**变好了**。

1. **基于生产环境生成设计稿**，必须和线上完全一致（同样的代码、同样的 token、同样的数据）。设计稿和线上有出入，就看不出到底是改动带来的变化，还是本来就有的差异。可参考用户级 skill `production-parity-prototyping`（不在本仓库内）。
2. **只调整有问题的位置，其他地方保持不变。**
3. 对比前后，确认**这一处**确实变好了。一次只动一个变量。

## 六、整体语义一致（宏观）

- 控制变量法偏**微观**，只能保证一个局部变好。
- 同一个**语义需求**在整个产品里必须保持一致（例如「次要说明文字」在每个页面都应是同一种处理）。
- **局部和谐不代表整体和谐。** 局部改完后，要回看整体：同一语义的其他出现位置是否仍然一致；不一致就要么一起改，要么说明为什么例外。

## 七、动手前的检查清单

- [ ] 这是层级问题还是布局问题？
- [ ] 每个区块里的信息颗粒度一致吗？
- [ ] 对齐 / 重复 / 亲密 / 对比，哪一条没做到？
- [ ] 能不能用松紧、大小、轻重、粗细描述它？
- [ ] 这次改动会用到 / 新增 / 修改哪些 design token？（先盘点，再动手）
- [ ] 设计稿是不是基于生产环境生成的？
- [ ] 改完后，同一语义在别处是否仍一致？
