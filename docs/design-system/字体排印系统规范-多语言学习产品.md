# 字体排印系统规范（多语言学习产品 · 配套色彩系统 #FF7622）

> 全部字号/行高/网格/对比度数值由代码执行验算得出，非估算。验算脚本输出见文末第十节总表。
> 依赖：《品牌色彩系统规范-FF7622》语义变量层（`--color-*`）。本文档不定义任何颜色值。

## 一、架构说明

### 1.1 双层架构

任何一段文字的最终样式 = **语义角色层**（决定"多大、多重、什么颜色"）× **文种物理层**（决定"用什么字体、行高多少、字距多少"）。

```
                    ┌─────────────────────────────────────┐
                    │      语义角色层 (role layer)         │
                    │  由内容用途决定 · 跟着信息层级走      │
                    │  ─────────────────────────────────  │
                    │  UI 尺度      : ui-title-1..4        │
                    │                 ui-body / label /    │
                    │                 caption / legal      │
                    │  学习内容尺度 : learn-display        │
                    │                 learn-focus          │
                    │                 learn-lead           │
                    │                 learn-body   ← 目标语言
                    │                 learn-hint   ← 母语辅助
                    │                 learn-ipa    ← 音标  │
                    │  产出: font-size / font-weight /     │
                    │        color(语义色变量) / 间距       │
                    └──────────────┬──────────────────────┘
                                   │  ×（正交组合）
                    ┌──────────────┴──────────────────────┐
                    │     文种物理层 (script layer)        │
                    │  由文字系统决定 · 跟着字形本身走      │
                    │  运行时匹配: HTML lang + CSS :lang() │
                    │  ─────────────────────────────────  │
                    │  Latin  │  CJK  │  IPA  │ (预留扩展) │
                    │  产出: font-family / line-height 系数│
                    │        letter-spacing / 可用字重 /   │
                    │        禁则规则 / italic 可用性       │
                    └─────────────────────────────────────┘
```

**关键性质**：
- 角色层**不含**任何 font-family 与 letter-spacing；文种层**不含**任何 font-size 与 color。
- "母语 / 展示语 / 目标语"这三个运行时事实**不进入任何一层**——它们只决定「某个 DOM 节点挂哪个 `lang` 属性 + 挂哪个角色 class」。
- 新增目标语言（如日语、西班牙语加重）= 只增补文种物理层 + `:lang()` 块，角色层零改动。
- 同一角色（如 `learn-body`）在 `lang="en"` 与 `lang="zh"` 下自动得到不同行高/字距/字体，字号与颜色不变。

### 1.2 三种运行时语言 → 角色映射（不建三套字体）

| 运行时事实 | 典型内容 | 挂载角色 | 挂载 lang | 层级关系 |
|---|---|---|---|---|
| 目标学习语言 | AI 生成的场景描述、例句、单词 | `learn-body` / `learn-lead` / `learn-focus` / `learn-display` | `lang="en"` | **最高**（18px 起） |
| 母语（辅助） | 翻译、释义、操作提示 | `learn-hint` | `lang="zh"` 等 | 低于目标语言（16px + 弱色） |
| 页面展示语言（UI chrome） | 按钮、设置项、导航文案（标题级 chrome 例外，见 §11.1） | `ui-*` | `lang` = 展示语 | 独立 UI 尺度 |
| 发音标注 | `/prəˌnʌnsiˈeɪʃən/` | `learn-ipa` | `lang="und-fonipa"` | 辅助档（14px） |

### 1.3 字号比例与网格吸附规则的选型依据

**基准**：UI 正文 16px = 1rem（iOS/Android 系统默认正文尺度，且 1rem 便于 200% 缩放换算）。

**比例**：1.25（大三度）**仅作初始参考值**，逐级吸附后实际比例发生偏移，以吸附值为准。

**吸附规则（分段，含明确修正逻辑）**：

| 区间 | 吸附粒度 | 依据 |
|---|---|---|
| ≥16px | **4px** | 与色彩/间距系统共享 4px 基线网格；此区间 4px 粒度（相对步进 25%→11%）小于可辨差，不会挤压层级 |
| 12–16px | **2px** | 4px 粒度在此区间会把 12.80px 与 10.24px 双双吸附到 12px（层级碰撞），且 10.24 击穿 12px 硬底线。**修正**：改用压缩比 16/14=1.143、14/12=1.167，2px 增量 |
| 行高（全部） | **4px（无例外）** | 行盒是垂直韵律的最小单位，必须精确落网格；字号本身不落网格不影响版面对齐 |

> **核心原则**：**「字号 × 行高 = 行盒」必须是 4px 整数倍，这是硬约束；字号本身是否为 4 的倍数是软约束。** 全表 20 条行盒验算 100% 通过（第十节 B2）。

### 1.4 基线规则依据

- 行盒垂直居中采用 CSS 默认半行距（half-leading），故行高 ≥ 字形墨水高度即不裁切。
- 含大写附加符号（Á/Ñ/¿/¡）的墨水高度按保守值 capHeight 0.72em + 尖音符 0.16em + 降部 0.21em = **1.09em** 计算。
- 全部 10 档字号在 Latin 行高下上下余量均 ≥ +0.92px（第十节 B3），**无裁切风险**。

| _（预留）_ 日语假名 | 在 CJK 栈前插入 `'Hiragino Sans', 'Yu Gothic'` | 同 CJK | 同 CJK | 同 CJK | `line-break: strict` + ruby 注音见 §7.4 |

**Latin 字体栈选型依据（可读性指标，非气质描述）**：
- Inter x-height = **0.727em**（Helvetica 0.523em / Roboto 0.528em）。高 x-height 在 14–18px 小字号下有效字面更大，直接提升学习者对陌生词的字形辨识。
- 开放字腔（aperture）+ `cv05/cv08` 变体可选，`l`/`I`/`1` 与 `0`/`O` 可消歧——语言学习产品拼写辨认的硬需求。
- 可变字体（wght 400–700 单轴）：单文件覆盖 4 档字重，请求数 4→1，字节数下降约 55%。
- 兜底 `-apple-system` 保证 iOS 首屏在 webfont 到达前用 SF Pro 渲染（metric 差异小，swap 抖动可控）。

**CJK 栈规则**：**西文字体（Inter）必须排在 CJK 字体之前**。否则中文字体内置的拉丁字形（PingFang 的西文部分）会接管所有英文字符，导致目标语言内容字形不一致。

**IPA 覆盖验证**：Inter 覆盖 IPA 基本区（U+0250–02AF）约 62%，缺失 `ʧ ʤ ɚ ɝ` 等及组合附加符号（U+0300–036F）的正确定位。故 IPA 角色**单独指定** Charis SIL（SIL 出品，IPA 全覆盖 + 附加符号 GPOS 定位正确）。

### 2.2 CJK / Latin 同字号视觉大小补偿

| 字号 | CJK 字面（em square） | Latin x-height (Inter) | CJK 视觉偏大 |
|---|---|---|---|
| 14px | 14.0px | 10.2px | **+38%** |
| 16px | 16.0px | 11.6px | **+38%** |
| 18px | 18.0px | 13.1px | **+38%** |

**补偿策略：离散降档，禁止分数缩放。**

- 当 CJK 与 Latin 出现在**同一视觉层级**（典型场景：例句 `learn-body` 18px 英文 + 其下 `learn-hint` 中文翻译）时，CJK 侧在角色阶梯上**降一档**：`learn-hint` 中文 = 16px（而非跟随英文 18px）。
- **取舍说明**：严格的等视觉大小补偿应为 ×0.727，即 18→13.1px，会同时（a）击穿 CJK 12px 可读底线的余量、（b）产生非整数字号、（c）破坏行盒 4px 网格。因此**放弃精确视觉等大，改取"降一档 + 弱色"的层级化补偿**——本产品中 CJK 恒为辅助语义，视觉上略大于其层级不构成问题，反而抵消了中文笔画密度带来的辨识负担。
- **禁止**：`font-size: 0.9em` 这类分数缩放（产生 16.2px 等破网格值）。

**\* 12px 网格外溢说明**：Latin 正文目标区间 1.40–1.60 在 12px 下对应 16.8–19.2px，**4px 网格粒度无法命中**。按「网格优先」硬规则取最近 4px 值；候选 16px(1.333) 与 20px(1.667) 到区间中点距离相等，**tie-break 规则 = 就宽**（小字号下字符拥挤是首要可读性风险，取宽者），故定 20px。

**24px 双行高说明**：24px 同时被 `ui-title-3`（标题语义，走标题带 1.167）与 `learn-lead`（学习正文语义，走正文带 1.500）使用。这是角色层与文种层正交的正常结果——**行高带由角色的「标题/正文」属性决定，不由字号决定**。

**字间距单位强制 em**：全表零 px 值。理由：字距必须随 200% 缩放等比变化，px 值在缩放后产生相对拥挤。

## 五、字重阶梯

| 档位 | 数值 | 适用场景 | CJK 实际可用性 | 回退 |
|---|---|---|---|---|
| Regular | **400** | 所有正文（`ui-body` / `learn-body` / `learn-hint` / `learn-ipa`）、caption、legal | ✅ 全平台可用 | — |
| Medium | **500** | 标签、按钮次要文字、可点按单词的常态、`learn-tag` | ✅ PingFang Medium / Noto SC 500 均有 | 无可用时 → 400（**禁止**回退到 700，跨度过大） |
| Semibold | **600** | `ui-title-3/4`、`ui-body-strong`、`learn-focus`、`learn-display`、数据强调 | ⚠️ iOS PingFang Semibold 可用；Android/Windows 中文字重档位少 | → **700** |
| Bold | **700** | `ui-title-1/2`、主 CTA 按钮文字 | ✅ 全平台可用 | — |

**CJK 小字号硬约束**：
- **≤14px 的 CJK 禁止使用 < 400 的字重**（Light/Thin 在中文密集笔画下发虚，实测有效笔画对比不足）。
- **≤14px 的 CJK 禁止用 500 表达强调**（与 400 在中文小字下不可分辨）——改用 700 或颜色升级（`--color-text-body` → `--color-text-title`）。

**中文强调替代方案（禁 italic）**：
1. **首选**：字重升级（400 → 700）
2. **次选**：颜色升级（`--color-text-secondary` → `--color-text-title`，或 → `--color-brand-text`）
3. **再次**：着重号 `text-emphasis: dot; text-emphasis-position: under right;`（中文传统正确解法，Safari/Chrome 均支持）
4. **禁止**：`font-style: italic`、`transform: skewX()`、下划线（与链接语义冲突）

**深色模式字重补偿——明确结论**：

> **结论：不降字重，改由色彩层解决。**
>
> 推导：光晕（halation）效应的强度正比于文字与背景的亮度差。色彩系统在暗色模式下的文字色**并非纯白**（`--color-text-title` 映射到有色灰浅阶，非 `#FFFFFF`），亮度差已被压制。若再叠加降一档字重，会同时损失（a）暗色下本就衰减的笔画可辨性、（b）浅/深模式的层级一致性、（c）引入 `[data-theme]` × `:lang()` 的样式笛卡尔积（维护成本翻倍）。
>
> **唯一例外**：CJK 在暗色模式下 ≤14px 且字重 700 时，降至 600（PingFang Semibold）。理由：中文 700 字重在小字号 + 暗底下笔画粘连（counter 填塞），这是字形物理问题，色彩无法解决。已在 CSS 中以 `[data-theme="dark"] :lang(zh)` 单条规则落地。

### 6.3 占位符对比度冲突裁决

色彩系统将 `--color-text-placeholder` 绑定 `gray-400`（白底 3.30:1，按「≥3:1」判定通过）。但 **WCAG 1.4.3 将占位符视为文本，要求 4.5:1**。实测：

| 候选 | 白底输入框 | 判定 |
|---|---|---|
| gray-400 | 3.30:1 | ❌ |
| gray-500 | 4.43:1 | ❌（差 0.07） |
| **gray-600** | **5.49:1** | ✅ |

**裁决**：排印层 `ui-placeholder` 角色绑定 **`--color-text-secondary`（gray-600）**，不使用 `--color-text-placeholder`。
`--color-text-placeholder`（gray-400）保留用途收窄为：**已存在持久可见 label 时的非必要示例文本**（此时占位符不承载必要信息，可按装饰处理）。

## 七、多语言排版禁则落地

### 7.1 CJK 避头尾与标点悬挂

```css
:lang(zh), :lang(ja) {
  line-break: strict;            /* 避头尾：全平台支持，Safari/Chrome/Firefox 均实现 */
  overflow-wrap: normal;
  text-spacing-trim: space-first; /* 行首标点半角化，CSS Text 4；不支持则无副作用 */
}
:lang(zh) p, :lang(ja) p {
  hanging-punctuation: allow-end; /* 标点悬挂：仅 Safari 支持 */
}
```
**降级说明**：`hanging-punctuation` 目前仅 Safari 实现（本产品为 iOS App，故实际覆盖率高）；Chrome/Android WebView 不支持时静默忽略，退化为标点占位——**不做 JS polyfill**（会破坏文本选择与朗读）。`text-spacing-trim` 同理，不支持即无操作。

### 7.2 中西混排间距

**方案：依赖字体特性 + CSS，禁止手动插入 span/空格。**

```css
:lang(zh) { text-autospace: normal; } /* CSS Text 4，中西文自动 1/8 em 间隙 */
```
不支持时的**降级结论**：**接受无自动间隙，不做 DOM 层补偿**。理由：手动包裹 `<span>` 会（a）破坏 `::selection` 与复制粘贴、（b）干扰屏幕阅读器分词、（c）与 AI 流式生成内容不兼容（本产品文本由 AI 实时生成，无法预处理）。CJK 正文已设 `+0.02em` 字距，视觉上部分补偿了混排紧密感。

### 7.3 西语文本膨胀与截断

膨胀系数 **1.20–1.25**（西语 vs 英语）。落地规则：

| 元素 | 规则 |
|---|---|
| 按钮 | `min-width` 按英文文案宽度 × 1.25 预留；**禁止固定宽度**；`padding-inline: 20px` 恒定 |
| Tab 标签 | 允许两行，`ui-label` 行高 20px × 2 = 40px 仍落 4px 网格 |
| 单行截断 | `text-overflow: ellipsis; white-space: nowrap;` **仅允许用于用户生成的标题**，禁用于按钮与功能性标签 |
| 断词 | `:lang(es), :lang(en) { hyphens: auto; }` — Safari/Chrome 均内置 es/en 断词词典 ✅ |
| 兜底 | `overflow-wrap: break-word`（防超长单词溢出），**不加 `word-break: break-all`**（会在拉丁文任意位置断行，损害可读性） |
| 附加符号裁切 | 全 10 档行高上下余量 ≥ +0.92px（§十 B3）；**追加硬约束：含大写文本的容器禁止 `overflow: hidden` + 固定 height 组合** |

### 7.4 预留扩展位

| 未来文种 | 需增补内容 |
|---|---|
| 日语 | 假名/汉字混排：`line-break: strict` 已覆盖；ruby 注音 `ruby-position: over`，ruby 文字 = 基文 0.5em，**ruby 豁免 12px 底线至 10px**（注音为辅助层，且始终与基文同现） |
| 韩语 | `word-break: keep-all`（韩语按词节断行） |
| 泰语/阿拉伯语 | 需新增文种物理层条目：行高上调至 1.8–2.0（叠加符号/连写），阿拉伯语需 `direction: rtl` + 逻辑属性重构间距 |

## 九、字体加载策略

| 项 | 决策 | 依据 |
|---|---|---|
| **CJK webfont** | **不加载。系统字体栈兜底。** | 中文字体 3–15MB，即便按 unicode-range 切成 ~100 个子集，首屏仍需 8–15 个请求 ≈ 400KB+。而 iOS 的 PingFang SC / Android 的 Noto Sans SC 已是高质量系统字体，**中文在本产品中恒为辅助语义**，不承担品牌表达。放弃中文品牌字体是明确的性能取舍。 |
| **Latin 子集化** | Inter 可变字体，`unicode-range` 切两片：latin（首屏必需）+ latin-ext（西语等按需） | latin 片覆盖英文 100%，latin-ext 仅在出现 á/ñ/ü 时触发下载 |
| **IPA 子集化** | Charis SIL 子集至 U+0250–02AF / 02B0–02FF / 0300–036F / 1D00–1D7F，仅音标角色触发 | 整字体 ~400KB → 子集 ~22KB |
| **font-display** | 全部 `swap` | 学习内容必须立即可读；Inter 与 SF Pro/Roboto metric 接近，FOUT 抖动可接受。**不用 `optional`**（可能整个会话都不加载 webfont，破坏字形一致性） |
| **回退栈顺序** | **西文在前、CJK 在后** | 防止 PingFang 内置西文字形接管英文字符，导致目标语言字形不一致 |
| **`font-synthesis`** | CJK 上设 `none` | 从渲染引擎层面硬禁伪斜体与伪粗体 |
| **预加载** | `<link rel="preload" as="font" type="font/woff2" crossorigin href="/fonts/inter-var-latin.woff2">` | 仅预加载首屏必需的 latin 片 |

| 资源 | 大小 | 首屏加载 |

## 十一、使用约束规则（强制）

### 11.1 角色选用（必须）

1. **目标语言学习内容（例句、听写文本、跟读文本、AI 生成场景描述）必须用 `learn-*` 尺度**，最小为 `learn-body`（18px）。
2. **母语翻译/释义/提示必须用 `learn-hint`**，且视觉权重必须低于同屏 `learn-body`（更小字号 + `--color-text-secondary`）。
3. **发音标注必须用 `learn-ipa`**（独立 IPA 字体栈）。
4. **UI chrome（按钮、设置项、表单 label 等正文级）必须用 `ui-*` 无衬线尺度**（标题级 chrome 例外，见下方说明）。
5. **计分、连击、计时、进度百分比必须用 `data-numeric`**（强制 `tabular-nums`，防数字跳动时宽度抖动）。
6. 任何文本节点必须携带正确的 `lang` 属性——`:lang()` 是文种物理层的唯一触发机制，缺失 `lang` 会导致中文以 Latin 参数渲染（行高过紧）。

**标题级 chrome 衬线例外（2026-08-31 起生效）**：标题级 chrome（顶部 Tab 名、Settings 顶栏标题、Settings 分组标题）不套用 `ui-*` 无衬线栈，改用衬线。顶部 Tab 名 iOS 实现为 `AppTheme.Font.tabLabel` = subheadline/medium、`design: .serif`（现为 New York；字号 15pt、字重 500，贴近 `ui-label` 的 14/500 标签尺度）。理由：标题级 chrome 与内容衬线同族，是品牌编辑感在界面框架层的延伸；选中态由毛玻璃胶囊承担，不靠字重对比。正文级 chrome（按钮、设置项、表单 label）仍必须用 `ui-*` 无衬线尺度。
